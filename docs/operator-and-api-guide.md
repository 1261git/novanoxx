# NovaNoxX v1.8 운영과 후속 개발 안내

기준일 2026-10-19. 실제 금융 실행·외부 심사 승인과 코드 구현은 별개입니다. 기존 운영/TEST DB와 파일, 미커밋 수정 및 백업은 보존합니다. 원래 요구 ID와 범위는 v1.8 PRD/기능정의서를 함께 확인합니다.

## 운영자 화면

- 프로필 메뉴 → 최근 본 에셋: 로그인 계정별 이 기기의 최근 7일/최대 30개. 목록 삭제는 이 기기의 기록만 지웁니다. 서버로 조회 기록을 추가 전송하지 않습니다.
- 프로필 메뉴 → 선택형 이메일 알림: 가격 변경/SOLD/새 에셋을 개별 선택합니다. 기본값 모두 해제. 새 에셋은 찜한 상품의 크리에이터 기준이며 과거 소식을 소급 발송하지 않습니다. 재설정 시 현재 상태를 새 기준으로 삼습니다.
- 선택형 메일에는 수신 철회 링크와 제공자용 List-Unsubscribe/One-Click 헤더를 넣습니다. 링크 열기만으로는 철회하지 않고 화면 버튼 또는 서명된 제공자의 POST로 철회합니다. 인증·주문 필수 메일은 별개입니다.
- 선택형 발송은 한국시간 08~21시, 사이트 전체 재시도 포함 24시간 5회/31일 100회 한도입니다. 종류별 회원당 하루 1개 원문을 큐에 넣습니다. 앱 메일량이 24시간 80건/31일 2,400건 수준에 이르면 새 선택형 큐 생성을 멈춥니다. 다른 서비스나 수신메일의 사용량을 포함한 제공자 계정 전체 청구액 보증은 아닙니다. 요금제/초과과금 설정은 변경하지 않습니다.
- 운영 관리자 → 에셋 심사 페이지 아래 검색 결과 없음 분석: 7/30/120일 선택. 동의한 검색 원문 중 결과 수 0인 검색어와 유입 도메인을 집계합니다. 계정 ID/IP/원문 개별 레코드는 이 화면에 반환하지 않습니다. 원문 삭제·120일 경과는 다음 집계에 즉시 제외됩니다.
- 동일 분석 영역의 실거래 지표: LIVE 승인 건수/총액/현재 환불액·완료 거래 수수료·구독 결제/환불 합계·실구매자/판매자·평균 주문액·같은 주문 생성 기간의 승인 전환율·활성 구독/에셋 상태, 독점 판매 가능 시간, 일반 주문/Brief 완료 시간. 기록 부족은 0시간으로 추정하지 않고 미표시합니다. 기간은 승인 시각 기준이고 환불액은 조회 시점 상태입니다. 판매자 송금액이나 확정 회계 수익과 혼동하지 않습니다.
- 판매 가능 시간은 최초 공개 승인부터 결제 승인까지 ACTIVE 구간만 합산합니다. PAUSED/RESERVED는 제외하고 MULTI·Brief는 이 평균에서 제외합니다. 과거 유상 예약/환불 후 재판매 등 정확한 재개 이력이 증명되지 않는 표본은 제외합니다. 완료 시간은 승인부터 COMPLETED 이벤트까지입니다.
- 초안 자동저장은 기존부터 브라우저 7일 복원 방식입니다. 서버 임시저장 버튼과 구분하며 파일이나 계약·권리 동의를 자동 제출하지 않습니다. v1.8의 자동저장 미확인 표기는 이 범위로 정정합니다.

## 계정 기능 API

응답은 JSON/no-store입니다. 로그인은 기존 HttpOnly 세션을 사용합니다. 임의 회원 ID를 요청에 받아 다른 회원을 조회하지 않습니다. JSON 변경 요청은 동일 Origin을 검증하고 본문 크기를 제한합니다.

| 경로 | 방식 | 권한과 입력 | 결과 |
|---|---|---|---|
| `/api/auth/email-preferences` | GET | 로그인 | version, price, sold, newAssets, updated |
| `/api/auth/email-preferences` | POST | 로그인/같은 Origin/JSON 1KiB 이하. version=`OPTIONAL_EMAIL_V1`, price/sold/newAssets boolean | 저장 후 현재 선택. 기존 소식 기준을 새로 설정 |
| `/api/auth/mail/optional-unsubscribe` | POST | 같은 Origin/JSON token, 또는 서명 token 쿼리와 `List-Unsubscribe=One-Click` 본문 | 선택형 전체 해제·미발송 큐 취소. GET은 변경 불가 |
| `/api/auth/admin/discovery-insights?days=30` | GET | 기존 최고관리자. days=7/30/120 | 동의 범위 검색/유입 집계와 LIVE 금융 지표. TEST 제외 |
| `/api/auth/finance/analytics?days=30&offset=0` | GET | 본인 크리에이터 | 기존 개인 성과, 페이지당25개 |
| `/api/auth/finance/view` | POST | 로그인/같은 Origin, 공개 assetId | 기존 비식별 일별 조회 집계 |

오류는 401(미로그인), 403(권한/Origin), 405(방식), 413(본문 한도), 415(JSON 형식), 400(입력 오류)로 구분합니다. 사용자 입력은 HTML로 삽입하지 않습니다. 관리자 통계는 읽기 전용입니다.

## 구조와 데이터

- `server.cjs` → `auth.cjs` → 계정/카탈로그/거래 HTTP 모듈. PostgreSQL 동기 호환 어댑터는 worker에서 연결을 관리합니다. 금융 실행은 각 계약/운영 플래그와 실제 제공자 조회 검증을 거칩니다.
- `engagement.cjs`: 선택형 알림 동의/현재 찜 상태 관찰 및 개인정보 범위 안의 검색 집계. 새 public 테이블 `account_email_preferences`, `account_email_observations`는 추가 생성하며 기존 테이블/행을 재작성하지 않습니다.
- `operating-insights.cjs`: 기존 주문/승인/환불/심사/이벤트 기록 읽기. 금전 청구, 잔액 변경, 원본 권한 부여를 수행하지 않습니다.
- `mail-worker.cjs`: 기존 백업 게이트 안에서 필수 알림 동기화 → 선택형 큐 생성 → 기존 암호화 outbox 발송. 선택형 생성 오류가 필수 발송을 중단하지 않도록 분리합니다. 발송 직전 동의·회원 상태·수신 거절·본인 이메일을 다시 확인합니다.
- 원문 검색은 기존 120일/별도 암호화 백업 90일, IP 미수집 정책 유지. 분석용 원문 복제 테이블은 만들지 않습니다. 최근 본 기록은 로컬 브라우저에만 저장합니다.
- 탈퇴 시 두 새 테이블의 해당 계정 자료를 정리하고 기존 outbox 취소·탈퇴 복구 필터를 유지합니다. 격리 복원 시 선택형 동의는 해제하여 옛 동의가 되살아나지 않게 하며 다시 선택해야 합니다.

## 배포와 복구

기존 운영 main 서비스만 사용합니다. 새 서버/작업자/크론/요금제/외부 메일 계정은 만들지 않습니다. On Commit 자동배포이면 push 후 중복 수동 배포하지 않습니다. LIVE 후 코드 버전·health·기존 이미지·소셜/메일 상태·새 접근 권한·새 화면을 확인합니다. 실제 운영 회원에게 시험 메일을 보내거나 금융 플래그를 켜지 않습니다.

기존 전체 암호화 백업과 Git 이력은 유지합니다. 이번 추가 테이블은 기존 전체 PG 백업 범위에 포함됩니다. 복원은 빈 격리 대상에서 메일·금융을 끈 상태로 시행하고 최신 탈퇴/철회 기록을 적용합니다. 새 선택형 동의는 복구 직후 해제합니다. 기존 백업 파일을 덮어쓰지 않습니다. 오프라인 개인키 복호화와 실제 전체 격리 복원 완료는 소유자 확인 대상입니다.

## 남은 경계

- 계약: 일반 PG/빌링/지급 운영 키·웹훅·KYC·재원과 최초 실금전 검수. 운영 NEON 원장 및 정산 후 회수/상계는 계약 조건 확정 후 추가 개발.
- 해외: 제공자/지원국·통화·환율·해외 지급 범위 미확정. 국내 코드와 번역만으로 완료 처리하지 않음.
- 데이터 범위: 검색 클릭·개별 행동 추적/추가 전환 분석은 기존에 동의한 수집 항목을 넘어 자동 활성화하지 않음. 기존 승인/주문에서 계산할 수 있는 지표와 구분.
- 외부 확인: 네이버 심사, 실제 보조기기/iOS/Safari/200% 확대·모국어/법률 감수, Figma 원본·외부 계정 권한과 계약상 기술 납품물 전수 확인.
- Phase 2 관리자 위임은 변경하지 않음. 이 문서와 소스별 API를 제공하며 전체 외주 계약의 완수 인증을 뜻하지 않음.
